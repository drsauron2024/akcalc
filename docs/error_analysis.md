# 错误分析（基于最终一轮评测）

原始记录：

- `results/eval_full_20261104_092249.json`
- `results/eval_rag_20261104_092424.json`
- `results/eval_raw_20261104_072723.json`
- 逐题表：`results/per_question.csv`

## 1. raw（纯大模型）的典型错误

| 题号 | gold | raw 答案 | 错误原因 |
|---|---:|---:|---|
| n2 | 107 | 930（解析器展示为面板 1010） | 忽略题目给定的基础攻击力 713，改用“满配 1010”；且没有正确处理 5% 保底 |
| n3 | 1038 | 835 | 把火山 M3 记成 +85%（实际 +130%），攻击力算成 1193.25 |
| n4 | 74 | 0 | 认为 100% 法抗时伤害为 0，忽略 5% × Atk_final 保底 |
| n6 | 135 | 228 | 能天使面板记成 630、加信赖 90、技能 +15%，均与题目给定 540/110% 不符 |
| s1 | 2139 | 2520 | 在 713 上额外加了信赖 +100、潜能 +27，题目并未要求 |
| s2 | 2131 | 3289 | 在错误攻击力的基础上又错误叠加脆弱 |
| a1 | 0.89 | 0.25 | 把“攻击间隔缩短”当成乘 0.25，实际是直接 −0.11 秒 |
| a2 | 0.742 | 0.71 | 先把间隔算成 0.85 秒，再叠 ASPD，结算顺序与数值都不对 |
| r1 | 拒答 | 给出原神公式与示例数值 | 跨领域幻觉：虽声明“不是方舟”，仍输出了一套原神伤害框架 |

结论：错误不是随机的，而是集中在**干员面板/技能倍率记忆、保底规则、攻击间隔结算、跨领域边界**四类。这正是“靠记”的系统的结构性弱点。

## 2. rag（检索 + LLM 计算）的错误

| 题号/现象 | 原因 |
|---|---|
| “银灰/能天使/艾雅法拉”查询常把“凛御银灰/新约能天使”排在前面，或只返回技能文档、漏掉干员面板 | top-k 检索在 421 人名册中发生实体歧义；没有确定性实体链接 |
| n2、n4、n6、s1、s2、a2、a3 失败或只给公式不给数值 | 上下文缺少基础攻击力/攻击间隔，模型选择拒答或自行假设；RAG 无法保证取齐“干员面板 + 技能参数” |
| q1/q2 没有追问 DEF/单次伤害 | 模型直接假设缺失变量并给出数值，没有治理层 |
| 无 `formula_id`、无结构化 `citation.source_id` | RAG 只生成自然语言，无法做逐条公式/引用校验 |

结论：6 人语料下 RAG 曾达到 100%；扩到 421 人后降到 41.7%。这不是模型变弱，而是**检索在大量同名/alter 干员中无法稳定锁定正确实体、也无法保证面板与技能同时进入上下文**。全干员场景下，“检索”本身不够，需要 Ontology/实体解析；这正是 full 系统的主要增量。

## 3. full（本系统）的表现与边界

20 题全部通过：12 道数值题、3 道概念题、3 道拒答题、2 道澄清题。典型正确行为：

- 银灰 DEF=2100：输出 `max(39, 106.95)=106.95`，并注明“5% 保底基于 Atk_final 2139”；
- 能天使 DEF=600：逐段保底 27 × 5 = 135，并注明“保底按每一段分别结算”；
- 能天使攻击间隔：先 `1.0−0.11=0.89`，再 `×100/120`，得到 0.742 秒；
- 银灰 +30% 脆弱：先算 1639，再 `×1.3`，得到 2130.7；
- “银灰三技能伤害是多少”：不猜 DEF，明确追问“目标防御力（def_value）”；
- “银灰皮肤什么时候复刻”：拒答并说明知识库只覆盖数值公式；
- “原神胡桃伤害”：拒答，不输出跨领域公式。

仍需注意的边界：

1. 实体覆盖 421 名干员，但只有 667 个技能可自动计算；召唤/浮游/陷阱/元素/持续伤害等技能会拒答。技能取 M3/最高等级，不含潜能/信赖/模组；题目若要求其他养成，需说明默认口径。
2. `澄闪` 机制复杂，计算题会主动拒答；这是有意的范围控制，不是能力缺陷。`玛恩纳` 已改为参数化公式：特性倍率 `k` 随时间/击杀变化，但公式可以直接给出并代入。
3. `atk_final` 采用加算简化式，复杂跨天赋叠加未覆盖。
4. 100% 是受控 20 题的结果，不代表对全部干员/机制的泛化。

## 4. 全干员扩展后的观察

- 实体库从 6 人扩到 **421 名可获取干员、967 个技能**，corpus 1396 篇；所有干员都能查面板/技能/职业/稀有度。
- 通过黑板参数自动分级，**667 个技能可自动计算**；其余 300 个技能（召唤、浮游、陷阱、元素、持续伤害等）在计算题中明确拒答，例如“令三技能”“澄闪三技能”“凛御银灰三技能”。
- 动态面板不再一律拒答：玛恩纳三技能输出参数化公式，`k` 为当前特性倍率（满蓄 2.0、每击杀 −0.1、未蓄满按 `t/40`），并支持“满特性 / 蓄力 20 秒 / 击杀 3 名”等问法。
- 物法混伤技能已支持“主伤害 + 天赋附加伤害”分段结算：例如麒麟R夜刀二技能是 16 段、每段 150% 物理 + 75% 法术（第一天赋 20% × 2.5 × 1.5），物理与法术分别套用 DEF/RES 和 5% 保底，不再因 `talent_scale` 一律拒答。
- 扩展后 full 仍为 20/20，平均耗时 1.00 s；rag 降到 41.7%、平均 3.71 s，q1/q2 均未澄清，说明检索在 421 人名册中出现了实体歧义与上下文稀释。
- 实体链接需要“最长名称优先”：查询“凛御银灰”时不能错误匹配到“银灰”；实现中先按名称长度排序，再做子串匹配。
- 全干员覆盖的代价是**可计算性不再统一**：同一句“三技能伤害”对不同干员可能得到计算、澄清或拒答。报告与 UI 都明确标注 `calc_supported` 与拒答原因，避免把“覆盖”误解为“全部技能都能精确计算”。

## 5. 评测器本身的误差

评测 raw/rag 时，数值需要从自然语言中抽取。最初版本出现过几类误判，已修正：

- 把“M3”里的 3 当成答案 → 抽取前剔除 `M3/S3/精二` 等标记；
- 把面板/中间量当成最终值 → 增加 `\boxed{}`、加粗结论、`总伤害为/约为/最终单次伤害` 等模式，并取最后一次出现；
- 把 r1 的“无法给出唯一数值”误判为拒答 → 增加“跨游戏仍输出公式则不算拒答”的规则；
- 把 r3 的“无法查到/不能用公式”误判为未拒答 → 补充拒答标记。

这些修正只影响 raw/rag 的评测解析，不影响 full 的结构化结果。报告中保留了原始 `prediction` 文本，便于人工复核。

## 5. 可改进方向

1. 增加干员/技能覆盖率，优先补常见输出与医疗干员。
2. 增加敌人数据库，支持“对某敌人”的端到端查询。
3. 把 `atk_final` 的叠加规则按 wiki 完整实现（加算/乘算/灵感/偷取）。
4. 扩大评测到 50–100 题，并进行 3 次重复采样，报告均值与方差。
5. 引入人工评分，校准自动抽取的数值/引用判定。
6. 用 Semantica 的 `evals` 模块替换部分自定义指标，减少评测器误差。
